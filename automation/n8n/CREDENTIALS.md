# n8n Credentials

Create credentials in n8n; never place their values in workflow JSON, Postman files, screenshots, or commits.

## QC Automation Key

- Type: `HTTP Header Auth`
- Display name: `QC Automation Key` (exact)
- Header name: `x-automation-key`
- Header value: the backend `AUTOMATION_SHARED_KEY`

This credential protects inbound n8n webhooks and authenticates every backend automation request. After import, confirm it is selected on all webhook nodes and all HTTP nodes whose URL begins with `QC_BACKEND_BASE_URL`.

## Messaging providers

The notification workflows contain provider nodes that must be linked to tenant-appropriate Twilio/email credentials before activation. A shared provider account may be used only when the sender identity and compliance policy support every tenant. Otherwise duplicate the worker by provider account or resolve provider configuration through a controlled backend dispatch service.

## Local checklist

1. Use a non-production `AUTOMATION_SHARED_KEY` in both the backend environment and `QC Automation Key` credential.
2. Set `QC_BACKEND_BASE_URL` to the backend URL reachable from n8n.
3. Import the workflows and resolve each credential placeholder.
4. Keep messaging nodes disabled or use provider test credentials until payload/tenant tests pass.
5. Never paste the Retell API key into Postman; Retell webhook signatures are generated by Retell itself.
